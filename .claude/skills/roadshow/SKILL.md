# 路演与答辩（Litz 黑客松专用）

## 事实源（本 skill 每次启动必读，顺序固定）

1. `ROADSHOW.md`（工作目录）— 手册：3 分钟结构、五类评委问题、ARG 框架、场景矩阵、hook 规则
2. `findings.md` — 调优日志，**所有结果数字的唯一可信来源**
3. `BATTLE_PLAN.md` — 里程碑勾选状态，决定讲稿里哪些内容"能讲"
4. 赛题 md 的评分表（`三维Litz线赛题 2/`）— 讲稿每段对标评分条目

**第一红线**：讲稿 / 海报 / 答辩中出现的每一个数字，必须能在 findings.md 或 sim 输出 CSV 中找到出处。找不到就写 `【待补：出处】`，禁止编造、禁止凭记忆沿用旧值。
**第二红线**：钩子、类比、具象化翻译必须物理诚实——「8 W/m ≈ 每米线烧掉一台手机充电器的功率」可以，「烧掉一台电磁炉」不行；夸大量级一旦被技术评委识破，全盘失信。

## draft：生成 / 更新 3 分钟讲稿

1. 读四个事实源；**未完成的里程碑只字不提**（BATTLE_PLAN 里没打勾的不上台）
2. 按 ROADSHOW §一 四段结构出稿：陷阱审计 30s → 网站演示 90s → 方法链 30s → 数字收尾
3. **开场 10 秒公式**：给谁、什么场景、什么时间、什么具体问题——四要素缺一即重写开场句
4. **三大问题完整性**：什么问题 / 什么创新方案 / 为什么是现在·为什么是我们（why-now 候选见 ROADSHOW §六，一句即可）
5. 每个数字后 inline 标注出处（`findings.md:L12` / `q1_solid/out.csv`）；交付版保留出处，背诵版可去
6. 输出两版：**full 版**（带出处）+ **3×5 卡片版**（每段一张，只有关键词和数字）
7. 网站演示段写成操作脚本：点哪里、说什么、预期画面，每个动作带失败分支（→ 切备份视频）；**双人分工版**：一人主讲、一人操作 Demo，别一人包揽
8. **评分对标**：每段末尾标注对应的赛题评分条目（例：方法链段 ↔ 网格收敛 5 分；演示段 ↔ 网站 12 分）——没挂到评分条的段落要么砍要么并
9. 若发现新里程碑完成而讲稿未更新，主动提出更新（不是等用户问）

## poster：路演海报

- 一页竖版（A1/A0），结构：**标题=结果数字+一句话价值主张** → 问题 + 陷阱审计（1 个最狠的）→ 方法链图（Bessel 锚点→FEM→切片→3D 对照）→ 核心图 2 张（D vs Rac/Rdc 相关性 + 网格收敛/三法互证）→ 网站 QR 码 + 团队（成员写实际承担的工作，不罗列头衔）
- 图从 `web/`、`paper/` 现有产物取，**不新造没有仿真支撑的图**；「爆炸图」位用结构分解图/方案族谱图替代
- 全页正文 ≤120 字；caption = 结论句；按"2 米外可读"定字号（正文 ≥24pt，标题 ≥72pt）
- QR 指向部署后的公开 URL；生成后用手机实扫验证一次

## booth：游园会 / 展位 / 海报现场（渐进式披露）

路人停留 10 秒决定走不走。做**三层脚本**，全部从 PITCH.md 压缩而来：

1. **10 秒钩子层**：一句强数字或一个同构道具，让人停下。规则：钩子与产品同构（无关噱头反噬）、10 秒内听懂要解决什么、能顺滑衔接下一层。候选见 ROADSHOW §六。**避坑：别在钩子环节现场首演 Demo**——用预热好的页面或备份视频
2. **60–90 秒电梯层**：五步——强数字开场 → 我们做什么 → 不解决的后果 → 新旧对比（一个数）→ 邀请亲手体验（网站调参）。不自我介绍
3. **5 分钟全讲层**：PITCH.md full 版按对方身份裁剪（技术评委→方法链加厚；企业/工业方→制造落地一句）

配套：
- **团队分工**：引流（喊钩子）/ Demo 操作 / 技术讲解各司其职；**全员口径对齐**——以 findings.md 和 PITCH.md 为唯一口径，对不上的一律以 findings.md 为准
- **交互挑战**：让评委亲手调 N、α 看损耗实时变化（网站的换参 UI 就是挑战装置）；挑战即体验，体验即说服
- 判断对方层级再深入：感兴趣 → 电梯层 → 主动问 → 全讲层

## drill：答辩演练（对抗模式）

扮演评委，共三轮，每轮结束才给反馈；开练前先问清评委构成（技术/企业/高校），按受众调整答案海拔：

1. **第一轮**：五类问题各 1 题（模型选择 / 假设 / 数据验证 / 参数确定 / 分工理解），从 ROADSHOW §二 预案出发现场变体，不许照念
2. **第二轮**：追问链——对每个回答追问一层：「误差量化了吗？」「换 500kHz 还成立吗？」「为什么不反过来？」
3. **第三轮**：两个杀手锏各一次——① 故意把问题指向"非主讲人"；② 问一个我们**没做过**的方向，检验是否「承认 + 从原理现场推断」而不是编造

加分练习（游园会抗打断）：任意时刻喊停，要求 30 秒内从当前段位接回主线。
话术：「这点路演时间不够展开，答辩环节我详细说」——路演没讲完的不是损失，是答辩的弹药库。

**评分**：每个回答按 ARG 三要素打 0–2 分（Answer 直接 / Reason 原因 / Ground 证据）。总分 <70% 输出弱项清单：缺数字 → 回 findings.md 取；缺推导 → 写成备用页；某队员某类题连挂 → 标记为 H44 演练重点。
**红线重申**：标准答案里没有的，承认没深入、给原理推断路径，永不编造。

## checklist：演示前检查

- [ ] 网站全部页面点通（含移动端视口）；录 60–90s 操作备份视频并**实际播放验证**
- [ ] PDF 备份一套；讲稿卡片打印；**钩子页预热打开**（不现场冷启动 Demo）
- [ ] 脱口而出数字清单（以 findings.md 实时值为准核对一遍）
- [ ] **彩排 ≥3 遍，其中 ≥2 遍带计时**，最终压到 2:45 以内（留提问缓冲）
- [ ] 双人分工对位排练一次（主讲 × Demo 手的交接点）
- [ ] 团队口径对齐会 10 分钟：人人过一遍数字清单 + 钩子层台词
- [ ] 实物道具检查（若用线材对比钩子：Litz 线 / 实心线各一段，贴标签）
- [ ] 向主办方确认的海报规格回执（若已确认，写进 poster 模式参数）

## polish：文风去模板化

按 ROADSHOW §三执行：删路标词、长短句交替、模型选择写权衡过程、局限必须带数字、保留真实探索痕迹（findings.md 里的弃案和翻车记录就是素材）。

决赛 3 分钟版**全部大白话**：公式名、方法学名留给答辩，台上只说人话和数字。
**数字具象化翻译**：每个关键数字配一个物理诚实的可感对照（8.01 W/m ≈ 每米线烧掉一台手机充电器的功率；3.65 倍 ≈ 直流时的近四成热）。翻译只进讲稿不进论文。

**只改文风，数值和证据链一个都不动**；改完抽查每个数字仍能对回 findings.md。
