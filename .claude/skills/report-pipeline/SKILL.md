# 报告闭环流水线（Write → Audit → Critic → Fix → Repro）

经实战验证的报告生产模式：每份文档必经一轮闭环才算完成。用多 agent workflow 实现（三角色并行/串行按阶段）。

## 阶段
1. **Write**：作者 agent 只从数据文件取数（prompt 中列权威源+禁引陈旧文件清单），完成后返回章节+引用文件清单；
2. **Audit**（与 3 并行）：对抗数值审计员——逐数字对源 + 环境真跑复算 ≥5 处（见 numeric-audit）；
3. **Critic**（与 2 并行）：完备性批评员——对着评分表/需求清单逐项找缺口（severity: must/should/nice + 具体修法）；
4. **Fix**：按 must→should 落地修正（可派专职 fixer agent，要求逐项列 applied/skipped）；修正引入的新数字同样要有出处；
5. **Repro**：涉及"修正后数值"时必须重跑生成器再生数据（见 repro-verify），不许只改文字。

## 已知陷阱（实战教训）
- 作者 agent 的"换算"常错单位/顺序——审计必须复算而非查源；
- 修正是链式的：h∥ 修正 → 全部下游数字复算 → 图重绘 → 摘要更新，漏一环就自相矛盾（摘要带旧口径是最高频残留）；
- 批评员指出的缺口若需要新数据，与其标注"待补"不如当场跑（便宜的引擎几分钟）；
- 审计员可被授权就地修 mismatch（带修正值），但 fix 级改动要列清单防越权；
- 每轮闭环后 findings/日志追加一条，形成可答辩的勘误链——勘误链本身是质控实力的证据。

## 产出
审计过的文档 + 修正清单 + findings 追加记录。
