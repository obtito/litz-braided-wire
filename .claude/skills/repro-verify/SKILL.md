# 复跑验证（Reproduction Run）

**原理**：幻觉数据经不起真实重跑。凡是「由脚本生成、但审查者未亲跑」的数据文件，一律重跑其生成器并对 diff。

## 方法
1. 对每个入库数据文件找到生成脚本（grep 文件名字符串）；
2. 真实重跑（注意运行时长，长的先跑后台）；
3. 对比关键锚点（逐位浮点/逐字节文件）；
4. 判定：`reproduced`（diff 为空或锚点逐位同）/ `mismatch`（给出差值与 %）/ `cannot-reproduce`（原因）；
5. **mismatch ≥1% 即 hallucination-suspected**。

## 已知陷阱（实战教训）
- **数据文件早于代码修正入库**：文件 mtime vs 代码 git log 必查——曾被修正后代码重跑揭出「修正后 +0.00430」实为修正前输出（且重跑后判据翻 PASS，叙事反而更强）；
- 生成器入口常不是直觉文件（先读文件找 `__main__`/入口函数）；
- 确定性声称（"双跑一致"）自己再跑第三遍验证；
- 浮点逐位比较用完整 repr，别过 print 的舍入；
- 复跑后若覆盖了入库文件，审毕要 `git checkout` 恢复，别留脏工作区。

## 输出格式
```
[锚点名] 入库值 vs 重跑值 → verdict（含差%）
```
